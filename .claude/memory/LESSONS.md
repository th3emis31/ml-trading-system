# Lessons (mistakes and wrong assumptions — append-only, read every session)

Format: `- YYYY-MM-DD [area]: what went wrong → what to do instead`

- 2026-09-12 [setup]: Status files like *_COMPLETE.md are stale snapshots → never create new ones; use NOTES.md.
- 2026-09-12 [CRT EA]: Per-symbol presets must cover position management too. BE/trail distances were raw points sized for gold; on BTCUSD (Point 0.01) that trailed $1.80 behind price and 4 trades stopped out <1s after the modify.
- 2026-09-12 [pages]: A page 'loading' fine is not a page 'working': render it in a browser and read the text for null/NaN/[object Object]/stuck Loading, and compare panels against each other (tiles said SELL while plans said HOLD).
- 2026-09-12 [tooling]: Git Bash rewrites '/path' CLI args to Windows paths; set MSYS_NO_PATHCONV=1 when passing URL paths to node scripts. Headless Edge clamps window width; emulate phone viewports via Emulation.setDeviceMetricsOverride.
- 2026-09-13 [research]: The live model's label (close up in 3 bars) does not match how trades are judged (TP before SL over 24 bars); a model can be ~51% 'accurate' and still lose 60%. Judge models by after-cost trading results on a holdout, never by accuracy.
- 2026-09-13 [research]: A model that looks great on validation folds (PF 1.6-1.7) can collapse on an untouched holdout; always keep a holdout that selection never sees, and prefer simpler models when data is only a few thousand bars.
- 2026-09-13 [mt5]: Never call MetaTrader5.initialize()/copy_rates/shutdown() from a second Python process while app.py holds its MT5 connection - the app process restarted right after such a read-only query. Read broker candles through the app's own connection (an app endpoint) instead.
- 2026-09-13 [research]: Best-of-63 selection on small validation samples (33-65 trades) produced validation PF 2.2-3.5 that collapsed on holdout. Require per-fold consistency (R9) and more trades (lower timeframes via broker data) before trusting any pick.
- 2026-09-13 [research]: This PC has ~7.4 GB RAM shared with app.py, MetaTrader terminals and a browser; a full parallel research queue was stopped by the system for low memory. Run research one symbol per process with a free-RAM guard (>=1.2 GB) and RESEARCH_JOBS=4 threads. src/train.py used to import LSTMTrader at module level, loading TensorFlow (~1 GB committed) into every research process; it is now imported inside train_lstm_model.
- 2026-09-13 [research]: With ~1.2 GB free RAM, random-forest research pieces on 4h+MTF are killed by the memory monitor even at RESEARCH_JOBS=1, while logit/xgb pieces finish. Combine the finished pieces (a subset search is still validation-only selection) and note which pieces are missing, rather than retrying the same run.
- 2026-09-13 [research]: A holdout that falls in one strong regime (gold 2024-26 bull run) makes simple rules look great (breakout PF 1.46-1.56) even though they lost on every earlier fold. Always run the plain rules/baselines on the validation folds too, and only trust a model that is positive in BOTH validation and holdout.
- 2026-09-13 [MT4]: MT4 DID hot-reload a recompiled expert (Experts log: 'uninit reason 2' then 'loaded successfully'/'initialized'). Before telling the user to re-attach an EA, grep MQL4/Logs/<date>.log (UTF-16) for that sequence after the .ex4 compile time.
- 2026-09-13 [research]: The 'killed for low memory' research failures were the background-task memory monitor, not real OOM: the same rf/balanced gold 4h MTF piece finished in 186 s in the foreground. Measured usage (7.5 GB PC): Windows svchost ~0.9 GB, app.py ~1.1 GB private, MetaTrader ~0.8 GB, Claude ~0.8 GB, webviews ~0.7 GB, Roblox only 0.17 GB. Run research in the foreground; do not ask the user to close programs without per-process numbers. (PowerShell inside bash double quotes loses $_ - use a .ps1 file.)
- 2026-09-13 [app]: app.py runs under C:\Users\th_em\start_trading.bat, a 'goto start' keep-alive loop launched at login by the Startup shortcut SmartEntryProAI.lnk; it relaunches app.py 5 s after it exits. Restart the app by stopping ONLY the python app.py process and letting the loop start it. Starting another copy (Start-Process / python app.py) created two servers both listening on port 5000 with two MT5/MT4 bridge connections (11:27-13:30 on 13 Sep). Afterwards check: netstat -ano | grep ':5000 .*LISTENING' shows exactly one PID.
- 2026-09-13 [doctor]: Health checks must model how the app really gates execution: asset auto_enabled alone cannot trade (app._autonomy_should_execute also needs an active session and autonomy.auto_execute), so flagging it as a warning was a false alarm. Read the gate before classifying a flag.
- 2026-09-13 [jarvis]: JARVIS command handlers contained hard-coded replies claiming trades were executed with invented prices (gold 2510/2580 while price was 4348) and one-click autonomy enablement. When touching assistant/voice features, grep handlers for literal prices, percentages and 'executed' claims and confirm every trading-state change goes through an explicit confirmation.
